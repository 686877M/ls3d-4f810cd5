## Persistence design (why the extra wrappers)
`snapSched` stores only edits of custom activities and `loadProject()` re-snapshots the live ACT before `restoreSched()` runs, so a template schedule would be lost on file open. The template activities are therefore also snapshotted in `DATA.qa.act[id].a` (written by the `persist` / `projectJson` wrappers, skipped while a load is running) and rebuilt by `qaRestore()` after every load and at start-up. Base activities replaced by the template are remembered (`DATA.qa.dropped`, memory `QA.base`) so opening a project without the template brings them back.

## NOT tested / limits (honest)
- No visual review of layout at narrow width, dark theme or RTL pixel layout (one desktop screenshot only, see below if attached). No screen-reader check.
- Typical durations, crews, checklists, cube rule, retention / advance %, tender offsets, permit documents, maintenance intervals and cost weights are **generic samples to adapt**; they are not regulations, not prices, not design approval, and the quoted rules of thumb are the ones in `PROJECT_PHASES.md`. The permit rules table ships empty on purpose.
- Cost spreading is linear inside each activity; weights are shares, not unit rates. P.X's own `bacMap` / earned value is not fed from these costs (it still uses `getItems`); no push to P.X cost accounts.
- Levelling moves single activities by constraint, greedy, may leave overloaded days when nothing has float; it never lengthens the project.
- Concave plots: the mitred offset is checked but not a full straight-skeleton offset; large setbacks are refused rather than approximated. C.X units are taken as metres x the scale you type.
- G.X overlay uses an equirectangular plane around the first vertex (plot scale only).
- Hold-point blocking is enforced on completion (100 %). Starting work after an unsigned predecessor is reported by `qaViol()`, not prevented.
- Interaction with other chunks that rewrite ACT wholesale (R.X `xf_p6` replace of `src:'rx'`, `lbPxSync` of `src:'lb'`) was not exercised beyond the load/replace paths above. 4D build (`buildSite`) with the template activities was not inspected visually.
- `getItems` / Q.X cell link uses the first sheet when no sheet name is given; Q.X formulas are read from the engine cache (`qxGet`), only a number is accepted.
- Tests ran on a heavily loaded machine, one Chrome at a time.
