## What it adds
* **Pane** `pane:mep` (command `mep_open`): tabs Summary / Electrical / Plumbing and drainage / Low-current / Fire and ventilation / MEP routes and clash. Each sheet = form (bilingual labels, units, min/max), live calculation, results, **PASS / FAIL** rows with value and limit, notes, "representative values used" list, buttons **Calculate, Print report, Download report, Copy JSON, Reset to sample** (every button has a bilingual tooltip). Table-type inputs are typed rows (`name, value, ...`, `#` comment line). Inputs persist in `localStorage xto-mep` (project data: the privacy close-out wipes it, not on the KEEP list).
* **Printable reports** (`MEP.report`, `TOX.mepReport`, one document for all sheets `mep_report`): neutral titles ("Electrical load schedule", "Water supply: demand and pipe sizing"), method line, disclaimer box, inputs, results, checks, SVG, representative-value footnote. No project names, no script (except the Print button).
* **Ribbon**: the R.X stubs **Duct, Pipe, Cable Tray, Pipe Sizing, Check Duct Systems, Check Pipe Systems** now run MEP commands (found by name in `RIBM`; verified to exist). Commands `mep_open`, `mep_report`, `mep_demo_routes`, `mep_clash` have bilingual XDESC.
* **R.X geometry** for gap 11, through the same hooks as beams (`RVX.name/build/two/chain/fields/def/msg`): kinds `duct` (rect w x h or round d), `pipe` (d + insulation), `tray` (w x h). Element = polyline `pts:[[x,z,y]...]` (y = centre line above the level), `sys` code, level `lv`; two-click elements (R.X chain tool) carry `a,b,y`. One mesh per segment with `userData.rv = id`, so **`nv_clash` and the N.X item list see them like any beam** (category `R.X duct` ...). Elements also carry `a`/`b` so generic R.X code that expects line elements does not break.
* **Clash wrapper** `MEP.RT.clash` / `TOX.mepClash`: creates (or reuses by name) three tests in the Clash Detective data: *MEP vs structure (hard)* (tol 0.01 m), *MEP vs structure (clearance)* (0.05 m), *MEP vs MEP (hard)*; structure = wall, col, beam, floor, fslab, found, roof, stair, ramp. `nv_clash` itself is **not edited**.

## Sheets (21) and what they check
| id | sheet | method (names only) | pass/fail checks |
|---|---|---|---|
| el_load | Electrical load schedule | connected x demand factor per category x group diversity (IEC 60364 / NEC practice) | kVA <= utility approval, phase imbalance, rows valid |
| el_circuit | Circuit design: cable and breaker | Ib <= In <= Iz, ambient + grouping + installation derating, voltage drop, minimum size, PE size (IEC 60364 style) | Ib <= In, In <= Iz', VD <= limit |
| el_panel | Panel schedule and circuit design | per-circuit design, RCD 30 mA on socket / wet / water-heater / kitchen circuits, greedy phase balance | every circuit OK, RCD present, feeder + cumulative 5 % VD, imbalance |
| el_sc | Short-circuit estimate | transformer + cable R and X sum, c = 1.05 / 0.95, adiabatic, instant trip at far end (IEC 60909 style) | Icu >= Ik3, Ik min >= trip, S >= Ik sqrt(t)/k per node |
| el_earth | Earthing electrode | rod, rod group, plate, ring/foundation (screening formulas) | R <= target; TT touch voltage R x I(delta n) <= 50 V |
| el_lps | Lightning protection | IEC 62305-2 simplified risk (Ad, Nd, Nc, E), levels, rolling sphere, mesh, down conductors | provided level covers required E |
| el_light | Lighting design | lumen method, room index, UF curve, CIBSE / EN 12464-1 guide lux | lux >= target, spacing/height, W/m2 per room |
| el_sld | Single-line diagram | feeders from sub-tree demand, cumulative VD, **SVG generated** | feeder OK + cumulative VD <= 5 % per panel |
| pb_water | Water supply | Hunter fixture-unit curve (fit), velocity, Hazen-Williams or Darcy-Weisbach (Swamee-Jain), residual pressure | v <= vmax, v >= 0.6 (waived at smallest DN), residual >= min |
| pb_tank | Water storage and pump-up | persons x L/person/day x days, roof share, pump rho g Q H / eta | >= 1 day, ground tank half day + fire reserve |
| pb_hot | Hot water | energy balance, heat-up time, solar area from irradiation | element power, peak-hour energy, storage >= 50 % |
| pb_drain | Drainage and vent | DFU (IPC style tables) **or** DU K sqrt(sum DU) (EN 12056 style), Manning partial flow, slopes, vent, trap arm, manholes | drain/stack size exists, slope, self-cleansing 0.7 m/s, vent per trap, trap arm, manholes |
| pb_septic | Septic tank and soakaway | max(flow x retention, 180 P + 2000), percolation area P Vp 0.25, pit | Vp valid, well and boundary distances, pit depth |
| pb_sewer | Sewer connection check | slope x length vs level difference, cover | gravity possible, slope >= min, cover |
| pb_rain | Rainwater drainage | rational Q = C i A / 3600, downpipe (weir entry), half-round gutter (Manning), soakaway storage | downpipe, gutter, soakaway capacity |
| lc_dev | Low-current device schedule and riser | counts per room/floor, cable per run with slack and loop, **riser SVG**, patch panels, switch ports, PoE | longest link <= 90 m, PoE budget |
| lc_cctv | CCTV bit rate and NVR storage | sum bit rate x time (decimal TB), RAID usable, PoE | input bandwidth, bays, PoE |
| lc_fa | Fire alarm | detector coverage, loops, sounder level, sounder circuit drop, battery C = 1.25 (Iq Ts + Ia Ta) | battery exists, call points, sound level, end voltage |
| lc_icom | Intercom | star or bus cable length, supply current, end voltage | supply >= demand, end voltage |
| fv_fire | Fire-fighting | extinguishers by area and travel (NFPA 10 / EN 3 style), reel, standpipe, sprinkler class (EN 12845 style) demand, tank volume, riser Hazen-Williams, pump power | travel, tank volume, velocity |
| fv_vent | Ventilation and extract | ACH or per person + hood flow, main duct velocity and friction, fan power, make-up, stair pressurisation | velocity, friction, make-up >= 80 % |

Sample project = one consistent two-floor villa (31 kW connected, 61 W/m2 demand, 11 data outlets, 5 cameras ...); all 21 samples pass; the failing cases are in the tests.

## API (all return plain data; `TOX` is re-frozen like the other chunks)
`mepSheets()`, `mepDefaults(id)`, `mepInputs(id)`, `mepRun(id, inputs?)` -> `{ok, v, rows, tables, checks[{id,ok,val,lim}], pass, fails, svg?}` (invalid input returns `{ok:false, errors}`, never throws), `mepLast(id)`, `mepReport(id, inputs?)`, `mepReportAll()`, `mepSummary()`, `mepSld(inputs?)`, `mepRiser(inputs?)`, `mepSample()`, `mepOpen(group, id)`, `mepRoutes()`, `mepAddRoute({k,pts,w,h,d,ins,sys,lv})`, `mepClearRoutes()`, `mepDemoRoutes({clash})`, `mepClash({tol,clearance})`, `mepRouteBoxes(id)`.
Example: `TOX.mepRun('el_circuit',{kW:6,ph:'1',V:230,L:25,type:'KIT',method:'B',amb:40,ngrp:3}).v` -> `In 32, S 10, Izd 32.6, vdPct 1.17`.

## Demo routes
`mepDemoRoutes({clash:true})` adds 8 routes sized to the R.X wall box (supply-air main + 2 branches, round extract, cold + insulated hot water, fire main, cable tray, 2 % drain). With `clash:true` and a beam in the model, the main duct and the cold-water pipe sit inside the beam depth so `mepClash()` finds them; `clash:false` gives a clean layout (0 clashes with beam, column, slab, walls in the test). With no beams the routes are clean and the result says so (the villa RC template of the sibling session will give real beams).

## Honest limits - read before using the numbers
* **Tables are typed from memory of the usual textbook / standard tables and are REPRESENTATIVE**, each listed in the sheet ("Representative values used - verify against the code edition"): cable ampacity (copper / aluminium PVC, reference method C, conduit factor 0.85), ambient and grouping factors, demand factors, fixture units and discharge units, DFU pipe and stack capacities, EN 12056 stack capacities, Hunter curve fit, pipe inside diameters, hose-reel / standpipe / sprinkler class values, detector coverage, battery factors, bit rates, ACH. **No clause numbers are quoted.** Egyptian code values were NOT checked against the code book (not available here); NEC and IEC differ in several tables.
* Simplifications: voltage drop ignores temperature variation between loaded cable and ambient; short circuit uses an equivalent-star impedance sum with no motor contribution and a fixed transformer X/R 5; earth resistances are screening formulas (soil must be measured); lightning is the simplified risk method with typed C1..C5; lumen UF is one smooth curve + reflectance offsets, not a luminaire photometric table; Hunter fit covers flush-tank systems only; drain sheet sizes one critical path / one stack, not a network; fire pump and tank use a single design flow and single riser; ventilation sizes one main duct; low-current cable lengths use an average run per room, not routed lengths; CCTV bit rates are generic.
* The routes are demonstration geometry: they are **not** drawn in plan / section views, not in the BOQ, not exported to IFC (R.X code ignores unknown kinds; nothing crashed in the tests, but IFC export and Q.X quantities for MEP were NOT checked). Clash boxes are axis-aligned world boxes: a diagonal duct reports its box. Walls with door/window openings are tested piece by piece as R.X builds them (a duct through a door opening is fine, through the wall piece is a clash).
* Sheets are **not linked** to R.X rooms, fixtures or the Panel Schedules yet: inputs are typed tables (the sample is the demo villa). Linking rooms -> load schedule -> panels -> SLD and fixtures -> pb_water / pb_drain is the natural next step. Hot-water pipe insulation, booster pump curves, grease traps, cable trays fill, fire-pump curves, duct network balancing, VRF, earth-fault loop for TT/IT, harmonics, generator / UPS / PV sizing are not done.
* Not tested: real GPU, Firefox / Safari, Arabic layout by eye (pane checked in English; RTL page mirrors the form, looked fine in one screenshot), printing to a real printer / PDF (report HTML only), the ribbon buttons by physical mouse (commands and tool selection called through `XC[id].run()`, canvas clicks through `rvClick`), 3 repeats of perf.
* Name: global `MD` is already used by the media recorder (`c_office.js`), hence `MEP`. Storage key `xto-mep`.
